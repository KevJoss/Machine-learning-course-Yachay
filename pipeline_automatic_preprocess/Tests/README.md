# Tests

The datasets in the `data/` directory were generated by an AI to verify the robustness of the `DataFramePreparer` pipeline class across a variety of real-world conditions.

---

## Dataset Specifications

### `dataset_missing_values.csv`
- **Rows:** 120 | **Target:** `label` (binary: 0 / 1)
- **Features:** `age` (numeric), `income` (numeric), `score` (numeric), `city` (categorical, 4 cities), `gender` (categorical, M/F)
- **Edge case:** ~30% of values in every feature column are `NaN`. Tests that imputation (mean, median, most_frequent) correctly handles heavy missingness across both numeric and categorical columns.

### `dataset_all_numeric.csv`
- **Rows:** 120 | **Target:** `label` (binary: 0 / 1)
- **Features:** `feat_a`, `feat_b` (Gaussian), `feat_c` (uniform 0-1), `feat_d` (integer 1-9) — all numeric, no categorical columns.
- **Edge case:** No categorical features whatsoever. Tests that `cat_pipeline` and `CustomOneHotEncoder` / `CustomOrdinalEncoder` degrade gracefully when there are zero object/string columns to encode.

### `dataset_outliers.csv`
- **Rows:** 120 | **Target:** `label` (binary: 0 / 1)
- **Features:** `salary` (numeric, mean ≈ 5000), `age` (numeric, mean ≈ 35), `experience` (numeric, mean ≈ 8), `department` (categorical, 4 departments).
- **Edge case:** 5 injected extreme outliers per numeric column (values up to ±999,999 against a mean of ~5,000). Tests that `RobustScaler` and `StandardScaler` handle extreme outliers without breaking the pipeline.

### `dataset_binary_categorical.csv`
- **Rows:** 120 | **Target:** `label` (binary: 0 / 1)
- **Features:** `employed` (yes/no), `married` (yes/no), `gender` (M/F), `education` (high_school / university / postgrad), `age` (numeric), `credit` (numeric, Gaussian).
- **Edge case:** Multiple binary and low-cardinality categorical columns. ~20% NaN in `employed` and `credit`. Tests both `ONE-HOT` and `LABEL` (ordinal) encoding paths on purely binary categorical data.

---

## Running the Tests

> **Important:** `test_pipeline.py` must be run via `python -m pytest`, not `python test_pipeline.py` directly.
> Running it directly with `python` will silently do nothing because pytest's test discovery doesn't activate.

```powershell
# From inside the Tests/ directory
python -m pytest .\test_pipeline.py -v

# Or from the project root
python -m pytest pipeline_automatic_preprocess/Tests/test_pipeline.py -v
```
